# ctx smart

Select the files relevant to a task description, using embeddings and the call graph.

## Synopsis

```bash
ctx smart <TASK> [PATTERNS]... [OPTIONS]
```

## Description

`ctx smart` takes a task description and selects the files from your codebase that matter for it. It combines:

- semantic search, which finds symbols related to the task through embeddings,
- call graph expansion, which adds callers and callees of the matched symbols,
- token budgeting, which keeps the rendered output within `--max-tokens`.

Optional positional patterns scope the entire selection pipeline. ctx ORs literal
files, directories, and globs together, and both semantic matches and
call graph expansion stay within that scope. With no patterns, `.` selects
the whole repository.

## Prerequisites

Before using `ctx smart`:

1. Index your codebase: `ctx index`
2. Generate embeddings: `ctx embed`

## Options

| Option | Description | Default |
|--------|-------------|---------|
| `--max-tokens <N>` | Hard maximum for the complete rendered context, measured with `--encoding` | 8000 |
| `--include-oversized-top` | Allow the most relevant file to exceed the hard output maximum | false |
| `--depth <N>` | Call graph expansion depth | 2 |
| `--top <N>` | Top semantic matches to consider | 10 |
| `--provider <local\|openai\|ollama>` | Embedding backend for the query. It must match the provider that built the embeddings. `--openai` is a deprecated alias for `--provider openai` | `local` |
| `--explain` | Show why each file was selected | false |
| `--dry-run` | Show selection without file contents | false |
| `--count-only` | Count the selected, budgeted files without preview or context output | false |
| `--encoding <ENCODING>` | Tokenizer for selection and counting (`cl100k_base`, `o200k_base`, or `p50k_base`) | cl100k_base |
| `--stats` | Print count timing to stderr with `--count-only` | false |
| `-f, --format <FORMAT>` | Output format (xml, markdown, md, plain, json) | xml |
| `--show-sizes` | Show file sizes in the project tree | false |
| `--no-tree` | Disable the project tree in output | false |

## Examples

### Basic usage

```bash
# Select files for adding a new feature
ctx smart "add user authentication"

# Review files for fixing a bug
ctx smart "fix the login timeout issue"

# Search and expand only within Rust source and one contract file
ctx smart "change request validation" "src/**/*.rs" tests/contracts.rs
```

### With a token budget

```bash
# Limit to 4000 tokens for smaller context
ctx smart "implement caching" --max-tokens 4000

# Measure exactly that selected pack using the target model's tokenizer
ctx smart "implement caching" --max-tokens 4000 --count-only --encoding o200k_base
```

`--count-only` prints its count summary on stdout and diagnostics on stderr. It
takes precedence over `--dry-run` and `--explain`, so those combinations do not
print a selection preview or formatted context.

`--max-tokens` counts the complete rendered stdout document, including the
project tree and format wrappers. The selector may leave out a file that fits by
itself if adding its wrapper would exceed the limit. A top-ranked file larger than
the budget is left out too. Use `--include-oversized-top` only when keeping the
highest-ranked file matters more than a hard context-window limit.

A zero budget is rejected. `--dry-run` previews all relevant files on purpose,
because it does not produce a context document. Use `--count-only` to
inspect the budgeted selection.

Semantic mode requires a complete, compatible embedding corpus. If embeddings are missing,
incomplete, or were generated by another provider, model, or dimension, the command exits 2 and tells
you to run `ctx embed --force --provider <provider>`. With `--json`, stdout is a
single standard envelope containing the operational error.

In ctx v0.4.0, `--max-tokens` limits only the selected file contents, the top-ranked file is
always included even when it alone exceeds the budget, and missing embeddings produce empty
output with exit code 0.

### Explain the selection

```bash
# See why each file was selected (printed to stderr)
ctx smart "add logging" --explain
```

Output:
```
Selected 2 files (2045 tokens):

1. src/logger.rs (1200 tokens)
   - SemanticMatch: "init_logger" (score: 0.92)
   - CalledBy: main (depth 1)

2. src/config.rs (845 tokens)
   - Calls: load_config (depth 1)
```

### Dry run

```bash
# Preview selection without outputting file contents
ctx smart "refactor error handling" --dry-run
```

Output:
```
Would select 4 files (2891 tokens):
  src/error.rs (1245 tokens) - SemanticMatch
  src/handlers.rs (892 tokens) - CalledBy
  src/validation.rs (512 tokens) - Calls
  src/response.rs (242 tokens) - SemanticMatch
```

### Deeper call graph analysis

```bash
# Expand call graph further for complex changes
ctx smart "optimize database queries" --depth 4
```

## How it works

1. ctx embeds the task description and finds matching symbols.
2. For each matched symbol, it follows call edges up to `--depth` levels.
3. It ranks files by semantic similarity and call graph relevance.
4. It adds the highest-ranked files whose rendered output fits within `--max-tokens`.

## Output

The output uses the same formats as plain `ctx` (XML, Markdown, and so on):

```bash
# Get markdown output
ctx smart "add tests" --format markdown
```

## Tips

- Specific task descriptions give better results.
- Start with `--dry-run` to preview the selection.
- Use `--explain` to see and tune why files were picked.
- Increase `--depth` for changes with wide impact.
- Lower `--max-tokens` when the context window is small.
